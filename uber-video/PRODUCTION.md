# Render deployment

Deploy this app as one Node web service. The Git repository is a monorepo; select Blueprint path `uber-video/render.yaml` and root directory `uber-video`.

The build installs locked dependencies, runs backend tests and frontend lint, builds the frontend, and scans for accidental secret exposure. Render serves the SPA, API (/api), and Socket.IO from one HTTPS origin. One server instance is configured; shared socket storage and distributed order locking are required before scaling across instances.

## Required Render secrets

- DB_CONNECT: a hosted MongoDB connection with access from the Render service. Local MongoDB cannot be used from Render.
- JWT_SECRET: generated by the Blueprint (minimum 32 characters).
- MAPBOX_ACCESS_TOKEN: backend token.
- VITE_MAPBOX_TOKEN: browser-safe public token with suitable domain restrictions. VITE variables are always public.
- RAZORPAY_KEY_ID and RAZORPAY_KEY_SECRET: configure on the server only. Existing local keys are test-mode credentials.
- ADMIN_EMAILS: only the administrator accounts present in the production database. Never allowlist an unregistered public email.

All real .env files, logs, generated builds and credential files are excluded from Git. Only placeholder .env.example files are intended for source control. Ignore rules do not remove previously committed secrets from Git history.

## Checks

Run `npm test`, `npm run lint`, `npm run build` and `npm run check:secrets`. Run the database integration suite with RUN_TRIP_INTEGRATION=1; it creates and removes its own temporary database on the configured MongoDB server and does not modify application accounts.

After deploying, verify /health, registration/login, admin authorization, two separate rider/captain sessions, cancellation, tracking, chat, and test-mode payment capture and receipts. No deployment is complete until the hosted checks pass. Payment checkout and browser GPS still need interactive verification.
